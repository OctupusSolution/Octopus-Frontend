# 🔴 المشاكل الحرجة

## 1. رفع الصور مش شغال

**المشكلة:** مفيش أي صورة بتتحفظ، لا لوجو ولا favicon ولا صور الأصناف ولا صور الـ Public Link.

**السبب:**
- الـ backend بيطلب من Cloudinary يحفظ الصورة جوه فولدر، فـ Cloudinary بيحفظها باسم `folder/publicId`.
- لما الـ backend بيتأكد إن الصورة اترفعت، بيدوّر عليها **من غير اسم الفولدر**، فمش بيلاقيها، ويرجّع `menu.media.verification-failed`.
- كمان إعداد `AdminApiBaseAddress` لسه متوجّه على أداة محلية مؤقتة (shim) مش موجودة.

**الأثر:** أي حد بيرفع صورة بيشوف خطأ، والصورة مش بتتحفظ. باقي البيانات بتتحفظ عادي.

**المطلوب:**
- التحقق يدوّر بالاسم الكامل `folder/publicId`، أو التوقيع يستخدم `asset_folder` بدل `folder`.
- `resourceType` يرجع بحروف صغيرة (`image`).
- `AdminApiBaseAddress` يرجع لـ `https://api.cloudinary.com/v1_1/`.

**الحالة:** لسه. الكود الحالي لسه بيتحقق بالاسم من غير الفولدر.

## 2. دور المالك (Owner) مش بيتعمل، وصفحة الأدوار فاضية

**المشكلة:** أي بيزنس جديد صفحة "الأدوار والصلاحيات" بتاعته فاضية خالص، و`GET /v1/businesses/{id}/staff/roles` بيرجّع قايمة فاضية.

**السبب:** الـ backend فيه function اسمها `Role.CreateSystemOwnerRole` بتعمل دور المالك بكل الصلاحيات، بس محدش بينادي عليها. والـ seeder مكتوب فيه صراحةً إنه مابيعملش الدور ده.

**الأثر:**
- صاحب الحساب عنده كل الصلاحيات فعلاً، بس مفيش دور ظاهر يوضّح ده.
- مفيش حاجة يعمل منها "نسخ" عشان يبدأ دور جديد بكل الصلاحيات.

**المطلوب:** لما البيزنس يتفعّل، يتعمل دور Owner (`IsSystemRole = true`) فيه كل الصلاحيات، ويظهر صاحب الحساب كعضو فيه. أو الـ list يرجّعه محسوب (derived)، بس بنفس الشكل (`id` و`permissions`).

**في الـ frontend:** جاهز. هيعرض الدور ده أول القايمة، وعليه شارة "دور النظام"، ومسموح عليه النسخ بس.

**الحالة:** لسه. اتبعتت رسالة لفرجاني.

## 3. الـ token المنتهي أو الغلط بيرجّع 403 بدل 401

**المشكلة:** لما الـ token يبقى مش صالح، الـ backend بيرد بـ "مالكش صلاحية" (403) بدل "لازم تسجّل دخول تاني" (401).

**التجربة (27/9) على `/staff/roles`:**

| الطلب | الرد |
|---|---|
| token صالح | 200 |
| من غير token خالص | 403 |
| token متلاعب في توقيعه | 403 |
| token منتهي | 403 |

**الأثر:** الـ frontend مش عارف يفرّق بين "الجلسة خلصت" و"اليوزر مالوش صلاحية"، فمضطر يجدّد الـ token مع أي 403. ولو اليوزر فعلاً مالوش صلاحية، هيتعمل تجديد على الفاضي.

**المطلوب:** أي token مش صالح أو مش موجود يرجّع 401 في كل الـ endpoints، قبل فحص الصلاحيات.

**الحالة:** لسه، وطلعت أوسع من الأول.

## 4. الطلبات المتزامنة بترجّع 500

**المشكلة:** لما طلبين بيعدّلوا نفس الحاجة في نفس اللحظة، الـ backend بيقع بخطأ 500.

**التجربة (27/9):** 12 طلب `PUT .../builder-progress` لنفس المنيو في نفس اللحظة: 5 نجحوا، و**7 رجعوا 500** `unexpected.error`.

**السبب:** `DbUpdateConcurrencyException` مش متعالجة.

**الأثر:** اليوزر ممكن يشوف "حدث خطأ غير متوقع" لو ضغط بسرعة أو فاتح الصفحة في تابين. الـ frontend اتظبط عشان مايبعتش نفس الطلب مرتين، بس ده مش كفاية.

**المطلوب:** الخطأ ده يترجم لـ 409 `concurrency.stale` في كل الـ modules.

**الحالة:** لسه.

## 5. تفعيل دخول الموظف بيرجّع 500

**المشكلة:** `POST /staff/members/{id}/login/enable` بيرجّع 500.

**السبب:** إعداد `Staff:InvitationTransport:KeySecretRef` مش موجود في الـ docker-compose.

**الأثر:** مفيش أي دعوة موظف هتشتغل.

**المطلوب:** إضافة `Staff__InvitationTransport__KeySecretRef` والـ secret بتاعه في الـ compose، زي مفاتيح الـ OTP.

**الحالة:** لسه. الإعداد مش موجود في الـ compose، والكود لسه بيقع من غيره.

## 6. `migrate.sh` ناقصه قواعد بيانات

**المشكلة:** سكريبت الـ migrations بيطبّق 6 قواعد بيانات بس: Master، وTenancy، وIdentity، وPublicLink، وMenuRouting، وMenu.

**الناقص:** `PublicLinkContentDbContext` و`OrderDbContext`، وباقي الـ modules اللي ليها tenant chain خاص (Staff، وReservation، وFloorPlan، وWaitingList، وCrm).

**الأثر:** بعد أي تحديث، الـ Public Link بيرجّع 500 (`column p.manifest does not exist`) لحد ما حد يطبّق الـ migration يدوي.

**المطلوب:** إضافة كل الـ tenant chains لـ `migrate.sh`، أو إنها تتطبّق تلقائي.

**الحالة:** لسه.

## 7. module مش موجود في الـ build بيوقّف البيزنس كله

**المشكلة:** لو البيزنس مشترك في module مش موجود في النسخة الشغالة من الـ backend، **كل** طلبات البيزنس بترجّع 409 `entitlements.invalid-state`، مش الـ module ده بس.

**السبب:** `TenantEntitlements.ResolveAsync` بيرجّع `InvalidState` للبيزنس كله لو لقى module code مش متسجّل.

**الأثر:** البيزنس بيقف كله: المنيو، والموظفين، والحجوزات، والـ Public Link.

**المطلوب:** الـ module اللي مش معروف يتجاهل، ويتكتب warning في الـ log.

**الحالة:** لسه في الكود. مش ظاهرة دلوقتي بس، لأن النسخة الحالية فيها كل الـ modules.

**المطلوب:** يتحمّل الملف في الـ worker، أو يتعمل Default profile.

**الحالة:** لسه.

## 9. التسجيل بإيميل موجود قبل كده مالوش رد واضح

**المشكلة:**
- التسجيل بإيميل متسجّل قبل كده بيرجّع نجاح (200)، ومش بيبعت أي إيميل.
- `verify-email` بيقبل **أي كود** لو الحساب متحقّق قبل كده.
- إعادة إرسال الكود بترجّع نجاح ومش بتبعت حاجة في حالات كتير، زي أول 30 ثانية.

**الأثر:** اليوزر بيستنّى كود مش هييجي.

**في الـ frontend (حل مؤقت):**
- تحت خانة الكود فيه سطر بيقول إن الإيميل المسجّل مش هيوصله كود، ومعاه رابط تسجيل الدخول.
- لو الحساب طلع موجود، بتظهر رسالة "هذا البريد مسجّل بالفعل" ومعاها زرار تسجيل الدخول.

**المطلوب:**
- يرجّع 409 بكود `identity.account.email-taken` (الـ frontend جاهز له)، أو يبعت للإيميل ده رسالة "عندك حساب بالفعل".
- `verify-email` مايقبلش كود غلط.
- إعادة الإرسال ترجّع الوقت المتبقي بدل ما تسكت.

**الحالة:** لسه. اتجرّبت بالمتصفح.

**المطلوب:** provider للـ dev يكتب الكود في الـ log، أو endpoint للـ dev بس يرجّع آخر كود.

**الحالة:** لسه. فيه provider اسمه `InMemory` بيحفظ الإيميلات في الذاكرة، بس مفيش أي طريقة نقرا منه.

## 11. إيميلات Brevo: السبب مش بيظهر في الـ log

## 22. الـ catalogue مش بيرجّع كل الحدود

## 23. مفيش طريقة تغيّر المحتوى المربوط بقسم

## 24. أسامي الـ catalogue مفاتيح ترجمة بس

الـ catalogue بيرجّع مفاتيح زي `sections.hero.fields.title` من غير نص. الـ frontend مترجم 100 مفتاح، وأي حاجة جديدة هتظهر إنجليزي. **المطلوب:** نص عربي وإنجليزي جنب المفتاح. **الحالة:** لسه.

## 25. شكل الـ header لكل صفحة مالوش قيم

الحقل بيقبل أي نص، ومفيش ولا theme بيحدد اختيارات ليه. الـ frontend مش عارض الحقل ده. **المطلوب:** قايمة اختيارات في كل theme، أو يتشال الحقل. **الحالة:** لسه.
