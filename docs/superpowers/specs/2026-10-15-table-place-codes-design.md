# Table Place Codes — wire the Table QR page to the backend

**Date:** 2026-10-15
**Backend source of truth:** `octopus-backend` `main` @ `d63848aa`, `specs/011-table-qr-codes/` (contracts/http-endpoints.md, features-permissions.md) and `Octopus.Modules.Menu.Contracts/Dtos/PlaceCodes/*.cs`.
**Sub-project 1 of 3** (1 place codes · 2 guest self-ordering · 3 public link US-019).

## 1. Goal

The merchant's **Table QR Codes** page (`/reservations/floor-plan/qr`, Figma 2012:185145) already exists but keeps every code in `localStorage` (`qr-store.ts`) with a random, unscannable code. Replace that with the backend's place codes so a branch manager can generate, print, disable, replace, re-link and revoke a code per table, and the state is the same on every device.

**Success:** generating codes for a floor, printing them, and disabling/replacing/revoking one all hit `/v1/businesses/{businessId}/menu/place-codes/*`; a reload or another browser shows the same state; nothing about codes is read from or written to `localStorage` except per-viewer print-layout preferences.

## 2. Decisions (agreed 2026-10-15)

- No Figma for the new parts; new UI follows the existing page's style (`qr/theme.ts`, `../../_shared/theme`), Arabic RTL + English LTR via `useI18n`.
- **Removed:** scan count / first scan / last scan. The backend deliberately has no scan statistics.
- **Not touched:** the menu Theme step's single access code with `?l=Table NN` (`pages/menu/build/theme/qr-panel.tsx`).
- No mock-api work: `apps/mock-api` does not serve menu routes today; the page is exercised against the real backend.
- Status names stay the page's own (`active | reprint | notGenerated | disabled`); the client maps backend `needsReprint` ↔ `reprint`.

## 3. Architecture

```
packages/api-client
  contracts/place-codes.ts      DTO types (1:1 with the C# records, camelCase)
  lib/place-codes-client.ts     one function per route; symbol/bundle return Blob
  index.ts                      re-exports

apps/merchant/src/pages/reservations/floor-plan/qr
  place-codes-api.ts            NEW  React hook layer: usePlaceCodes(floorId) — floors, rows, counts,
                                     attention, lastPrint; refetch after every mutation; maps DTO → view
  qr-store.ts                   SHRINKS to view types + statusOf(row) + downloadFile; localStorage removed
  index.tsx                     reads usePlaceCodes instead of useTableQr
  generate.tsx                  calls generatePlaceCodes; design step loads/saves the server design
  table-qr-modal.tsx            detail + actions + activity tab
  print.ts                      prints server symbols (blob URLs) instead of the local encoder
  attention-panel.tsx           NEW  suspended codes list with "re-link to candidate"
  relink-modal.tsx              NEW  pick a target table on the plan
  print-history-modal.tsx       NEW  print runs list + re-download bundle
```

`useFloorPlan()` stays the source of the drawn plan. Rows are joined to plan tables by `resourceId` (= `FloorTable.id` for published tables; verify during implementation, fall back to matching by `number`). The page sends the published floor's id as `floorId`.

## 4. Data flow per feature

| Feature | Route(s) | Behaviour |
|---|---|---|
| Overview counts, legend, last printed | `GET /place-codes/floors`, `GET /place-codes?floorId=` | counts from the list response; `lastPrint` replaces the local max-of-dates |
| Status per table on the plan | `GET /place-codes?floorId=&size=500` | one call, all rows; zone filter stays client-side over the drawn plan |
| `hiddenFromCustomers` | row field | small marker on the table (eye-off icon) |
| Generate (select → design → review) | `POST /place-codes/generate` | selection maps: individual→`one{resourceId}` — several hand-picked tables become sequential `one` requests (each with its own `batchId`), shown with one progress bar; if one fails the loop stops, the done tables keep their codes and the review screen names the failed one with Retry (unlike the other modes this is not all-or-nothing); zone→`zone`, range→`range{from,to}`, all→`all`. `existing: keep` by default; choosing "replace existing" sends `regenerate` + `confirmReplaceCount` = number of already-coded tables in the selection. `batchId` = `crypto.randomUUID()` made once per review screen, so a retry replays. |
| Print / download after generate | `POST /print-runs` then `GET /print-runs/{runId}/bundle` (ZIP) or per-code `GET /{codeId}/symbol?format=svg` | the run is recorded **before** any file is fetched (backend rule). Print window uses the SVG symbols; "Download" saves the ZIP. |
| Table modal — details | `GET /place-codes/{codeId}` | status, version, generated by/at, printed count, last printed by/at, never-printed badge; `address` shown with copy button when present (only for print/manage holders) |
| Disable / Enable | `POST /disable` · `POST /enable` with `codes:[{codeId, expectedRevision}]` | also bulk from the overview ("Disable all in zone") via `floorId + selection` |
| Replace (regenerate) | `POST /{codeId}/regenerate` | confirm dialog: "the printed sticker stops working"; afterwards offer Print |
| Re-link | `POST /{codeId}/relink {resourceId}` | relink modal picks a table on the plan; 409 `relink-target-taken` shows which table holds it |
| Revoke | `POST /{codeId}/revoke` | destructive confirm, typed as final; table returns to `notGenerated` |
| Activity tab | `GET /{codeId}/activity` | timeline (Generated, Disabled, Enabled, Relinked, Revoked, Printed, Exported; actor, time, place); if `history.complete=false` show "N entries missing" + **Rebuild** (`POST /activity/rebuild`, manage) |
| Attention list | `attention[]` in list response | panel above the plan: codes whose table left the floor; button "Re-link to {candidate}" when `candidate` exists, else Re-link modal or Revoke |
| Design | `GET` / `PUT /place-codes/design {expectedVersion,…}` | server fields: `templateKey`←template, `sizeKey`←qrSize, `labelStyle`←numberStyle, `showLabel`←showNumber, `message` (≤60), `primaryColour`←primary. `logoAssetId` stays null in this sub-project (local logo upload kept local). Paper, margins, perPage, background, qrStyle, tentSize remain per-browser print preferences in `localStorage`. 409 `design-stale` → reload design, toast. Saving a changed design flips printed codes to `reprint` (server-side) → refetch. |
| Print history | `GET /print-runs?page=`, bundle | modal list: when, who, count, format; re-download ZIP |

Every request id sent as `operationId` / `batchId` is generated once per user action and reused on retry.

## 5. Error handling

ProblemDetails `errorCode` → translated toast (en + ar) for: `menu.place-code.not-found`, `…revoked`, `…stale` (refetch and say "changed by someone else"), `…place-not-on-floor`, `…place-already-coded`, `…relink-target-taken`, `…floor-not-published` (send user to the floor plan builder), `…selection-too-large` (>500), `…confirm-count-mismatch` (refetch, re-show confirm), `…design-stale`, `…selection-invalid`, `…selection-empty`, `rate.limited` (symbol: retry after a moment).
- **403 `entitlements.feature-not-enabled`** (`menu:place-codes` not purchased) → the whole page shows an "add-on not enabled" empty state instead of the plan.
- **403 `authorization.forbidden`** on an action → toast "you don't have permission"; on the list → read-only empty state. Action buttons are not hidden in advance (no client permission helper exists); they fail politely.
